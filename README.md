# Проектная работа 3 спринта: Цифровая трансформация банка «Стандарт»

## Описание
В данном репозитории представлены артефакты, разработанные в рамках планирования цифровой трансформации банка «Стандарт». 
Цель проекта — спроектировать архитектуру и план перехода для запуска онлайн-каналов обслуживания (открытие депозитов и кредитов), чтобы привлечь новую аудиторию и повысить конкурентоспособность банка.

Работа выполнена в формате "Infrastructure as Code" и "Documentation as Code".

## Задание 2. Управление требованиями (FURPS+)

Цель задания — собрать, структурировать и приоритизировать требования к системе цифровой трансформации, учитывая функциональные потребности бизнеса и нефункциональные ограничения существующего ландшафта.

### Результаты
*   **Таблица требований FURPS+**
    Полный реестр требований, разбитый по категориям:
    *   **F (Functionality):** Основные сценарии для клиентов (онлайн-заявки) и сотрудников (обработка).
    *   **U (Usability):** Требования к единому дизайну, скорости отклика UI и поддержке через кол-центр.
    *   **R (Reliability):** Доступность 99.9%, защита АБС от перегрузки.
    *   **P (Performance):** Время отклика API < 200мс.
    *   **S (Supportability):** Использование существующего стека (Java, Oracle, .NET).
    *   **+ (Constraints):** Переход на микросервисы для новых функций, использование Kafka, шифрование.

## Задание 3. Концептуальная архитектура MVP "Открытие депозитов онлайн" (ADR)

Цель задания — спроектировать архитектуру решения для запуска MVP (Minimum Viable Product), которая позволит быстро вывести продукт на рынок (Time-to-Market), минимизируя риски интеграции с устаревшей АБС и закладывая фундамент для будущей микросервисной платформы.

### Ключевые архитектурные решения
В ходе анализа требований принято решение о **частичном переходе на микросервисную архитектуру** с использованием паттерна **Strangler Fig**:
1.  **Выделение нового домена:** Создание независимого кластера микросервисов (`Deposit Service`, `Rate Service`) вместо доработки монолита.
2.  **Защита Legacy:** Внедрение **Anti-Corruption Layer (ACL)** в виде `АБС API Layer` для защиты базы данных АБС от прямой нагрузки.
3.  **MVP-компромисс:** Использование ручной обработки заявок сотрудниками бэк-офиса на первом этапе для исключения рисков сложной интеграции "на запись" в АБС.

### Артефакты
*   **Architecture Decision Record (ADR)**
    Полное описание архитектурного решения, включая контекст, альтернативы, диаграммы и анализ рисков.

*   **Диаграмма контекста (C1 Context)**
    Визуализация взаимодействия новых и существующих систем с пользователями и внешними сервисами.

    *(Исходный код: [C1_Context_Deposit_MVP.puml](./Task3/C1_Context_Deposit_MVP.puml))*

*   **Диаграмма контейнеров (C2 Container)**
